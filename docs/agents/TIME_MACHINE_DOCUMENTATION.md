## 1. Executive Summary & Quantitative Mandate

The **Time Machine Agent** acts as an empirical probability gatekeeper within the Delta Exchange 11-agent multi-agent algorithmic trading pipeline. Unlike naive backtesters or curve-fitted optimizers, the Time Machine's explicit mission is **trade-setup validation through walk-forward historical simulation**. 

Before any trade proposal generated by the Strategy Agent can reach the Risk Gatekeeper or request 2-way human authorization via Telegram, the Time Machine back-tests the exact market setup against historical multi-timeframe candle data. It verifies whether an identical technical edge historically produced positive mathematical expectancy ($\mathbb{E}[R] > 0$) after deducting real-world exchange frictions (maker/taker fees, order book slippage, and funding rate drag).

### Zero-Tolerance Mandate for Synthetic Approvals
In algorithmic execution, the worst possible error is a false positive: taking an unvalidated trade because of optimistic or synthetic backtest assumptions. The Time Machine operates under a strict **fail-closed** discipline:
- If candle data is missing, gapped, or corrupted $\rightarrow$ **`INSUFFICIENT_DATA` (VETO)**
- If historical trade matches are below sample size thresholds $\rightarrow$ **`INSUFFICIENT_SAMPLE` (VETO)**
- If walk-forward out-of-sample expectancy is non-positive $\rightarrow$ **`REJECTED` (VETO)**
- Under no circumstances does the engine fabricate synthetic win rates or bypass statistical requirements.

## 3. Exact Strategy Historical Replay Architecture

To eliminate Strategy Replay Divergence, the upgraded Time Machine contains a dedicated **`HistoricalReplayAdapter`** that parses the incoming candidate setup's `strategy_name`, `side`, and `confluence` metadata, and evaluates the identical multi-factor conditions at each historical candle index $i$.

### Replayed Strategy Archetypes:
1. **`Institutional_SSL_Sweep` (Long):**
   - 1H trend alignment (1H Close > 1H EMA21 or 1H RSI $\ge$ 45).
   - Price sweeps below the 10-bar swing low on 15m (`low[i] < recent_low`).
   - Strong candle close back above the swept low (`close[i] > recent_low`).
   - Market Structure Shift (MSS): Bullish candle close (`close[i] > open[i]`) with RSI recovering above 40.
2. **`Institutional_BSL_Sweep` (Short):**
   - 1H trend alignment (1H Close < 1H EMA21 or 1H RSI $\le$ 55).
   - Price sweeps above the 10-bar swing high on 15m (`high[i] > recent_high`).
   - Strong rejection close back below swept high (`close[i] < recent_high`).
   - MSS: Bearish candle close (`close[i] < open[i]`) with RSI falling below 60.
3. **`Intraday_EMA_Pullback_Scalp_Long`:**
   - 1H Bullish trend confirmation (`close_1h >= ema21_1h`).
   - 15m pullback test: `low[i] <= ema21_15m * 1.002` and `close[i] >= ema21_15m * 0.998`.
   - RSI momentum corridor: $40 \le RSI_{15m} \le 75$.
   - Session VWAP alignment: `close[i] >= vwap[i] * 0.996`.
4. **`Intraday_EMA_Pullback_Scalp_Short`:**
   - 1H Bearish trend confirmation (`close_1h <= ema21_1h`).
   - 15m pullback test: `high[i] >= ema21_15m * 0.998` and `close[i] <= ema21_15m * 1.002`.
   - RSI momentum corridor: $18 \le RSI_{15m} \le 58$.
   - Session VWAP alignment: `close[i] <= vwap[i] * 1.004`.
5. **`Institutional_Bearish_Breakdown_Short`:**
   - 1H Bearish trend (`close_1h < ema21_1h`).
   - 15m breakdown: `close[i] < recent_low` and `close[i] < ema21_15m`.
   - Volume confirmation: volume $\ge 1.2\times$ 20-period SMA volume.
6. **`High_Volume_Momentum_Impulse` (Long/Short):**
   - Volume surge: volume $\ge 1.8\times$ 20-period SMA volume.
   - Decisive candle body: $|close - open| / (high - low) \ge 0.60$.
   - Directional alignment with EMA21 and Session VWAP.
7. **`Institutional_SMC_FVG_Retest` (Bullish/Bearish):**
   - Identification of 3-bar Fair Value Gap imbalance:
     - Bullish FVG: `low[k] > high[k-2]`
     - Bearish FVG: `high[k] < low[k-2]`
   - Current candle wicks into the gap zone (retest) and closes with rejection.

## 4. Multi-Timeframe Alignment & Lookahead-Free Synchronization

To execute authentic multi-timeframe validation without lookahead bias:
- **1H Candles:** Ingested with strict timestamp indexing. At historical decision bar $i$ (timestamp $T_i$ on 15m), only the 1H candle whose **close timestamp $\le T_i$** is exposed to the algorithm. 
- **15M Candles:** Primary structural and signal generation timeframe.
- **5M & 1M Candles:** Ingested when available to inspect intrabar execution. If sub-candle data is unavailable, the simulation enforces conservative ambiguity resolution.

```
Time Axis (t) ------------------------------------------------------------------------>
1H Candle K:    [============== OPEN ============================ CLOSE ]
                                                                     ^ (Only accessible AFTER close)
15M Candles:    [ 15m 1 ]    [ 15m 2 ]    [ 15m 3 ]    [ 15m 4 (Decision Bar i) ]
                                                                     |
                                             Can ONLY use 1H Candle K-1, NOT K!
```

## 5. Realistic Intrabar Event Sequencing & Ambiguity Resolution

When forward-simulating an active trade through historical bars:
1. **Chronological Processing:** For each forward bar $b \in [i+1, i+1+\text{sim\_bars}]$, evaluate price events chronologically.
2. **Ambiguity Resolution in Single-Bar Conflicts:**
   If a single bar's range spans both the active Stop Loss and the Take Profit (or Stop Loss and Breakeven Trigger):
   - **Check Sub-Candles (1M/5M):** If 1m or 5m candles exist for that bar, replay their chronological trajectory.
   - **Conservative Worst-Case Principle:** If sub-candles are absent:
     - **For Long:** If `low <= SL` and `high >= TP`, assume **SL was hit first** (Loss).
     - **For Short:** If `high >= SL` and `low <= TP`, assume **SL was hit first** (Loss).
     - **Breakeven Activation:** If `high >= BE_trigger` and `low <= initial_SL` in the same bar, assume **SL was triggered before the stop could be moved to entry**.
   - **Ambiguity Logging:** Every trade where conservative resolution was invoked is tagged with `ambiguity_resolved=True`.

## 6. Comprehensive Outcome Accounting & Realized PnL Mathematics

### Allowed Outcome Taxonomy:
1. **`WIN`:** Price reached or exceeded Take Profit target without violating active Stop Loss.
2. **`LOSS`:** Price touched or breached Stop Loss before reaching Take Profit.
3. **`BREAKEVEN`:** Stop Loss had been moved to entry ($+0.50R$ trigger achieved) and subsequently executed at entry price.
4. **`TIMEOUT`:** Trade reached `max_simulation_bars` without touching SL or TP. **Mandatory Action:** Evaluated and closed at bar close price $C_{\text{final}}$.
5. **`INVALIDATED`:** Candidate setup was cancelled prior to simulated fill.

### Trade-by-Trade Net R-Multiple Formulation:
For every simulated trade $k$:

$$\text{Gross PnL USD} = 
\begin{cases} 
\text{Contracts} \times \text{ContractValue} \times (P_{\text{exit}} - P_{\text{entry}}) & \text{for Long} \\
\text{Contracts} \times \text{ContractValue} \times (P_{\text{entry}} - P_{\text{exit}}) & \text{for Short}
\end{cases}$$

$$\text{Friction USD} = \text{Entry Fee} + \text{Exit Fee} + \text{Slippage USD} + \text{Funding Drag}$$

$$\text{Net PnL USD}_k = \text{Gross PnL USD}_k - \text{Friction USD}_k$$

$$\text{Initial Planned Monetary Risk USD} = \text{Contracts} \times \text{ContractValue} \times |P_{\text{entry}} - P_{\text{initial\_SL}}| + \text{Friction USD}_{\text{entry}}$$

$$\text{Realized Net } R_k = \frac{\text{Net PnL USD}_k}{\text{Initial Planned Monetary Risk USD}}$$

### Aggregate Quantitative Metrics:
- **Net Expectancy ($\mathbb{E}[R]$):**
  $$\mathbb{E}_{\text{net}}[R] = \frac{1}{N_{\text{filled}}} \sum_{k=1}^{N_{\text{filled}}} \text{Net } R_k$$
- **Gross Expectancy:**
  $$\mathbb{E}_{\text{gross}}[R] = \frac{1}{N_{\text{filled}}} \sum_{k=1}^{N_{\text{filled}}} \text{Gross } R_k$$
- **Profit Factor ($PF$):**
  $$PF = \frac{\sum_{k: \text{Net PnL}_k > 0} \text{Net PnL}_k}{\left|\sum_{k: \text{Net PnL}_k < 0} \text{Net PnL}_k\right|}$$
  *(If denominator is zero and profits exist, $PF$ is defined as $10.0$ max cap).*

## 7. Statistical Decision Gate & Confidence Bounds

### Wilson Score 95% Confidence Interval Lower Bound
To avoid trusting small-sample streaks (e.g., 3 wins on 3 trades):

$$w^- = \frac{p + \frac{z^2}{2n} - z \sqrt{\frac{p(1-p)}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}}$$

Where $p = \frac{\text{Wins}}{N_{\text{decisive}}}$, $n = N_{\text{decisive}}$, and $z = 1.960$.

### Bootstrap Expectancy Confidence Interval
$B = 1,000$ resamples with replacement from realized $\{\text{Net } R_k\}_{k=1}^N$ to compute the empirical 95% confidence interval $[R_{0.025}, R_{0.975}]$.

### Risk Ratios:
- **Annualized Sharpe Ratio:**
  $$\text{Sharpe} = \frac{\bar{R}}{\sigma_R} \times \sqrt{252 \times 4}$$
- **Sortino Ratio (Downside Deviation):**
  $$\sigma_{\text{down}} = \sqrt{\frac{1}{M}\sum_{k: R_k < 0} R_k^2}, \quad \text{Sortino} = \frac{\bar{R}}{\sigma_{\text{down}}} \times \sqrt{252 \times 4}$$
- **Maximum Drawdown ($MDD$):** Peak-to-trough drop in cumulative $R$ and cumulative dollar PnL.

## 8. Rolling Walk-Forward Validation Engine

Rather than an arbitrary 70/30 split, the engine partitions historical data into $K \ge 3$ chronological rolling windows.

```
Window 1:  [ Train: 50% ] ---> [ Embargo ] ---> [ OOS: 25% ]
Window 2:         [ Train: 50% ] ---> [ Embargo ] ---> [ OOS: 25% ]
Window 3:                [ Train: 50% ] ---> [ Embargo ] ---> [ OOS: 25% ]
```

### Embargo Period
Between the training window and the out-of-sample testing window, an **embargo buffer** equal to `max_simulation_bars` is enforced. Any simulated trade initiated near the end of training is prohibited from extending into the OOS evaluation set, preventing trade overlap contamination.

## 9. Delta Exchange Friction & Settlement Dynamics

- **Maker Fee:** $0.02\%$ ($0.0002$)
- **Taker Fee:** $0.05\%$ ($0.0005$)
- **Execution Model:** Market/Taker on Entry and Emergency Stops, Maker on Limit Take Profit. Round-trip fee baseline = $0.07\%$ to $0.10\%$.
- **Slippage Model:** Dynamic basis point buffer based on asset volatility and ATR ($0.03\%$ for BTC, $0.05\%$ for ALTs).
- **Funding Rate Drag:** $0.01\%$ per 8-hour funding epoch proportional to trade holding duration.
- **Contract Type Dynamics:**
  - **Inverse Perpetual ($BTCUSD$):** Quoted in USD, settled in BTC. Non-linear convexity handled via contract point value.
  - **Linear Perpetual ($ETHUSD$, $SOLUSD$):** Quoted and settled in USDT/USD.

The public signature is fully preserved:

def simulate_setup(
    self,
    setup: Dict[str, Any],
    candles_15m: Optional[Dict[str, Any]] = None,
    candles_1h: Optional[Dict[str, Any]] = None
) -> Dict[str, Any]

### Returned Verdict Codes:
- **`APPROVED`**: Setup passed empirical edge ($WR \ge 65\%$), positive EV ($\mathbb{E}_{\text{net}}[R] \ge +0.30R$), $PF \ge 1.50$, and rolling out-of-sample confirmation.
- **`REJECTED`**: Statistically sufficient data, but setup fails edge, EV, profit factor, or OOS robustness.
- **`INSUFFICIENT_DATA`**: Less than 60 valid historical bars or uncorrectable data corruption.
- **`INSUFFICIENT_SAMPLE`**: Fewer than `min_sample_size` (8) decisive historical setups found.
- **`VETOED_INVALID_PRICES`**: Inverted, non-positive, or nonsensical entry/SL/TP levels.
